- Loader support: Fabric only for now; NeoForge project is excluded from the active Gradle build.
- Build config uses Fabric Loader 0.19.3 and Fabric API 0.161.0+26.2.
- Altium mod ID: altium. Initial independent version: 0.1.0.
- Language: Java. No JNI/Rust native renderer in this project.
- Branding and Arch documentation are layered onto the 26.2 source baseline.

EXPERIMENT ORDER
1. Low-core worker priority experiment: on systems with <=4 logical processors, raise chunk-worker priority one level (NORM-2 -> NORM-1). Hypothesis: slightly reduce chunk completion delay; risk: increased CPU contention. Not validated until A/B testing.
2. Thread contention / worker sizing on low-core CPUs.
3. Rebuild scheduling under frame-time pressure.
4. Meshing allocation pressure.
5. Memory profile, then other renderer targets guided by measurements.

WORKING RULES
1. One experiment per commit or small series of commits.
2. Measure before and after using the same world, route, settings, warm-up, and sample length.
3. Track average and p95/p99 frame times, chunk-loading stutter, memory, and GC where practical.
4. Keep risky behavior behind a configuration toggle where feasible.
5. Preserve upstream license notices and third-party attribution.
6. CI success proves compilation/packaging only, not in-game correctness or a performance win.

RESULTS
Initial qualitative baseline: render distance 6; chunks load quickly while walking, with slight delay. User also observed fast loading at one chunk-builder thread. Repeatable FPS/frame-time measurements are still pending.
